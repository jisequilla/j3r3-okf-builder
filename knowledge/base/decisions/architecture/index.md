> A decision about how a system is built (ADR).

# Architecture decisions

* [ADR-0006: Python scripts without external dependencies](ADR-0006-dependency-free-scripts.md) - The tools (init, lint, index, migrate) are Python ≥ 3.9 without pip; PyYAML is used only if present. _(deprecated)_
* [ADR-0007: Single source of skills and per-platform projections](ADR-0007-single-source-and-projections.md) - Skills live only once in plugin/okf-builder/skills; each platform receives a projection (symlink or generated package).
* [ADR-0011: Scripts run with uv and declare PyYAML inline (PEP 723)](ADR-0011-uv-pep723-scripts.md) - The okf-standard scripts declare PyYAML in PEP 723 inline metadata and run with uv run, the reduced YAML parser is removed, and each script carries its own tests.
* [ADR-0013: One knowledge-architect agent for Claude and Microsoft 365 Copilot](ADR-0013-agent-projections.md) - The knowledge-architect agent is written once as a Claude plugin agent and generated into a Microsoft 365 Copilot declarative agent; other platforms keep using the skills until there is a need for their agent formats. _(deprecated)_
* [ADR-0017: The Claude agent preloads every skill it needs; the Microsoft 365 agent takes a configured subset](ADR-0017-agent-skills-per-platform.md) - The knowledge-architect agent is still written once as a Claude plugin agent and generated into a Microsoft 365 Copilot declarative agent, but only M365's caps bind M365; the Claude agent lists every skill the role uses, and tools/m365-agent.json picks the at most 8 skills the M365 agent carries.
* [ADR-0030: The projection tools are a script and a skill, run a render only on request, and list recomputable projections for a person](ADR-0030-projection-tools.md) - okf_projection.py checks projection.yaml, the dependency rule and drift by nature, and the okf-projection skill creates, refreshes and renders projections; okf_lint stays OKF-only; a rendered projection's render command runs only on an explicit flag; a recomputable projection is listed for a person to recompute; the skill ships in the M365 packages but not in the M365 agent. _(deprecated)_
* [ADR-0031: The projection tools are a script and a skill, run a render only on request, never ask a transient projection to be committed, and list recomputable projections for a person](ADR-0031-projection-tools-transient-exception.md) - okf_projection.py checks projection.yaml, the dependency rule and drift by nature, and the okf-projection skill creates, refreshes and renders projections; okf_lint stays OKF-only; a rendered projection's render command runs only on an explicit flag, and what it writes is compared file by file, a transient projection's files never required to be committed; a recomputable projection is listed for a person to recompute; the skill ships in the M365 packages but not in the M365 agent.
* [ADR-0032: A bundle opens as an Obsidian vault through a viewer setup that a script writes, not a projection](ADR-0032-obsidian-viewer-setup.md) - okf_obsidian.py writes .obsidian/app.json, with Markdown links kept relative and updated on rename, and knowledge.base, with five Bases views over base/ and fragments/, at a bundle's root without overwriting; it is workspace configuration for one tool, neither a knowledge projection nor a platform package; okf-init offers it, make obsidian runs it here, and this repository commits both files.
* [ADR-0034: An organization receives okf-builder as its own package, copied in by a reviewed pull request per release, and each of its repositories pins the version that checks it](ADR-0034-organization-package.md) - A new generated platform package, the organization package, writes okf-builder's skills, its scripts as an installable package and the organization's Domain Profile into a bundle of the organization's own marketplace through a reviewed pull request per release; each repository of the organization records the version in its root index and runs lint at that version from that marketplace, never from a copy; other OKF dialects the organization runs converge on this standard as Domain Profiles and validators. _(deprecated)_
* [ADR-0037: An organization receives a copy of okf-builder that it owns and versions, pulls later releases when it chooses, and runs lint from the installed plugin](ADR-0037-organization-distributed-copy.md) - The organization package, generated from a tagged release of okf-builder, delivers the skills with their scripts as plain files, the organization's Domain Profile and a pre-commit hook; once delivered the copy is the organization's, which may take it in its own direction and versions it by its own release process while recording the okf-builder version it was taken from; a later okf-builder release reaches it only when the organization pulls it, by a pull request in its own repository; its repositories run lint from the plugin each person installs, with no pinned version; the installable scripts package is deferred; other OKF dialects still converge as Domain Profiles and validators. Supersedes ADR-0034.
