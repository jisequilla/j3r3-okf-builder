> Architecture decision records (ADR).

# Architecture decisions

* [ADR-0001: Adopt Google's Open Knowledge Format as the basis of the standard](ADR-0001-adopt-google-okf.md) - Project knowledge is represented as an OKF bundle (markdown + YAML frontmatter) instead of a format of our own.
* [ADR-0002: One bundle per repository in knowledge/](ADR-0002-knowledge-folder-per-repo.md) - Each repo carries its knowledge in knowledge/, co-located with the code, not in a central repo.
* [ADR-0003: Profile directories and types in Spanish](ADR-0003-spanish-names.md) - Profile directories and type values are in Spanish, except references/ and Attested Computation, which the spec fixes. _(deprecated)_
* [ADR-0004: Support OKF v0.1 and v0.2, with v0.2 as the default](ADR-0004-dual-support-v01-v02.md) - The profile writes v0.2, reads and validates v0.1, and migrates in both directions without mixing forms in a bundle.
* [ADR-0005: generated required and verified only by people](ADR-0005-required-generated-human-verified.md) - The profile requires generated on every concept and forbids an agent from writing verified with a human: actor. _(deprecated)_
* [ADR-0006: Python scripts without external dependencies](ADR-0006-dependency-free-scripts.md) - The tools (init, lint, index, migrate) are Python ≥ 3.9 without pip; PyYAML is used only if present. _(deprecated)_
* [ADR-0007: Single source of skills and per-platform projections](ADR-0007-single-source-and-projections.md) - Skills live only once in plugin/okf-builder/skills; each platform receives a projection (symlink or generated package).
* [ADR-0008: The okf-builder repo documents its own knowledge with OKF](ADR-0008-dogfooding.md) - This repository applies profile knowledge/1.0 to itself; the project's decisions are ADRs in knowledge/decisions.
* [ADR-0009: Build multi-stage changes in layers and delegated tickets](ADR-0009-build-in-layers-and-tickets.md) - Changes that touch several layers of the repo are split into verifiable tickets that agents build in isolated worktrees, and the main session only judges, verifies and merges. _(draft)_
* [ADR-0010: English as the repo's canonical language and profile knowledge/2.0](ADR-0010-english-canonical-profile-2.md) - The profile vocabulary, the code, the skills and the repo's knowledge move to English, with a fixed glossary; the vocabulary change bumps the profile to knowledge/2.0. _(draft)_
* [ADR-0011: Scripts run with uv and declare PyYAML inline (PEP 723)](ADR-0011-uv-pep723-scripts.md) - The okf-standard scripts declare PyYAML in PEP 723 inline metadata and run with uv run, the reduced YAML parser is removed, and each script carries its own tests. _(draft)_
* [ADR-0012: Knowledge fragments are captured as they happened and distilled into the bundle](ADR-0012-knowledge-fragments-and-distillation.md) - A meeting, discussion or transcript is stored as an immutable Fragment concept, and a distillation step proposes the additions, updates and conflicts it brings to the bundle for a person to resolve. _(deprecated)_
* [ADR-0013: One knowledge-architect agent for Claude and Microsoft 365 Copilot](ADR-0013-agent-projections.md) - The knowledge-architect agent is written once as a Claude plugin agent and generated into a Microsoft 365 Copilot declarative agent; other platforms keep using the skills until there is a need for their agent formats. _(deprecated)_
* [ADR-0014: A knowledge repository has one source, Git or SharePoint; other tools read it](ADR-0014-knowledge-repository-storage.md) - A team's knowledge bundle has exactly one editable copy, a Git repository by default or a SharePoint library for teams without Git; Microsoft 365, Google Drive and Obsidian read it, and the bundle starts as one monorepo with a stated rule for splitting by domain. _(draft)_
* [ADR-0015: Knowledge fragments follow the KDD bundle's format, and conflicts go to one register](ADR-0015-fragment-format-and-conflict-log.md) - A fragment is a Knowledge Fragment with occurred_at, origin, participants and distillation_status; each bundle keeps one Conflict Log; okf-fragment, okf-distill and okf-review are separate skills, and distillation still needs a person's approval. _(deprecated)_
* [ADR-0016: Distillation adds refutation: an outdated concept is deprecated without opening a conflict](ADR-0016-refutation-as-a-distillation-kind.md) - Fragments keep the KDD format and one Conflict Log per bundle; distillation classifies each item as an addition, confirmation, update, refutation or conflict, where a refutation proposes deprecating a concept and naming its replacement, and only disputed items open a conflict. _(deprecated)_
* [ADR-0017: The Claude agent preloads every skill it needs; the Microsoft 365 agent takes a configured subset](ADR-0017-agent-skills-per-platform.md) - The knowledge-architect agent is still written once as a Claude plugin agent and generated into a Microsoft 365 Copilot declarative agent, but only M365's caps bind M365; the Claude agent lists every skill the role uses, and tools/m365-agent.json picks the at most 8 skills the M365 agent carries. _(draft)_
* [ADR-0018: A bundle has three layers, fragments, base and projections, in profile knowledge/3.0](ADR-0018-three-layers-fragments-base-projections.md) - The bundle separates what was said (fragments/), what is known (base/, holding the typed directories) and what is derived for a reader (projections/); moving the typed directories under base/ is a breaking change, so the profile becomes knowledge/3.0 with a migration from 2.0. _(deprecated)_
* [ADR-0019: Knowledge projections derive from the base for a reader, declared in a projection.yaml and checked for drift by content hash](ADR-0019-knowledge-projections.md) - A projection is a directory in knowledge/projections/ with a projection.yaml (lifecycle, nature, intent, refs with their hashes), its content and its rendered deliverables; it is not OKF and has its own tools, it never regenerates by itself, and this repository's per-platform outputs of the skills are renamed platform packages. _(deprecated)_
* [ADR-0020: A domain declares its own taxonomy in a Domain Profile concept, which lint and the skills read](ADR-0020-domain-profiles.md) - A directory under base/ may hold a profile.md of type Domain Profile that declares the domain's types (each extending a profile type), their typed fields, the questions the domain answers, its dependencies and aliases for local names; it applies to its directory and below, and the tools read it instead of a fixed list. _(deprecated)_
* [ADR-0021: A bundle has three layers in profile knowledge/3.0; open questions are concepts in base/ and action items live in the team's tracker](ADR-0021-three-layers-with-open-questions.md) - The bundle separates what was said (fragments/), what is known (base/, holding the typed directories) and what is derived for a reader (projections/), in profile knowledge/3.0; an open question is an Open Question concept in base/ with an owner, and an action item lives in the team's tracker, never copied into the base. _(draft)_
* [ADR-0022: Knowledge projections are declared in a projection.yaml, and their drift is checked according to their nature](ADR-0022-knowledge-projections-drift-by-nature.md) - A projection is a directory in knowledge/projections/ with a projection.yaml (lifecycle, nature, intent, refs, versions), its content and its rendered deliverables; it is not OKF; a rendered projection is checked by regenerating it and comparing, a composed one by the content hashes of its refs, and a recomputable one by running its procedure again; nothing regenerates by itself. _(draft)_
* [ADR-0023: A bundle declares its taxonomy in one Domain Profile, with families per directory, composition rules and profiles shared by reference](ADR-0023-domain-profile-per-bundle.md) - A bundle's base/profile.md of type Domain Profile declares its types, typed fields, families (a schema per directory), questions and optional aliases, extends shared profiles by reference and never copies them, and follows written composition rules (an extension only adds, a duplicate id is an error, forbidden, fixed, by_type, named rules, validator delegation); lint and the skills read it. _(deprecated)_
* [ADR-0024: A fragment's record is immutable, and a missing capture field may be backfilled once from the record itself](ADR-0024-fragment-capture-field-backfill.md) - Fragments keep the KDD format, one Conflict Log per bundle and five kinds of distillation item; after capture the record never changes, but a missing occurred_at, origin or participants may be filled once, with a value read from the record or from an original its sources cite, approved by a person and logged. _(draft)_
* [ADR-0025: generated is required, and an agent writes a person's verification only from that person's recorded answer to a question naming each concept and version](ADR-0025-verification-recorded-by-question.md) - Every concept carries generated and starts as a draft; verified with a human actor is written by the person, or by an agent after that person answers a structured question naming each concept and its version, kept verbatim as a fragment and linked from the log. _(draft)_
* [ADR-0026: The standard's own types are a built-in Domain Profile, the first layer under each bundle's profile, with a level per requirement and typed actors and timestamps](ADR-0026-built-in-domain-profile.md) - A bundle's base/profile.md declares its taxonomy as in ADR-0023, on top of a built-in Domain Profile shipped with okf-standard that declares the standard's types; requirements carry a level (error or warn), field types add actor, datetime and date_or_datetime, checks across concepts stay in code, and lint reads references locally, runs validators only on request, resolves aliases and warns on undeclared keys only in bundles with a profile. _(draft)_
* [ADR-0027: The owner of an operational concept is a string; Actor stays as the OKF spec defines it](ADR-0027-owner-is-a-string-actor-stays-the-spec.md) - On API, Metric, Playbook, Policy, Runbook, System and Table, owner is a string that names a team or a person, so team:<team> is valid; an Open Question's owner stays an actor, and the actor convention stays exactly the spec's, with no team prefix. _(draft)_
* [ADR-0029: A fragment records its frozen material by SHA-256 and may freeze a repository at a commit, through a map field type](ADR-0029-fragment-material-and-repository.md) - A Knowledge Fragment may list the files its record was taken from, each with its SHA-256, and the repository it was taken from at a full commit; the standard gains a one-level map field type to declare both, lint hashes material found in the bundle and reports a changed file as an error, and okf-fragment adds the meeting discipline. _(draft)_
