# Context

[ADR-0019](/base/decisions/ADR-0019-knowledge-projections.md) defined knowledge projections: a directory in `knowledge/projections/` with a `projection.yaml`, outside OKF, with a dependency rule, never regenerated by itself, and drift measured by the content hash recorded for each ref[^bundles]. It also renamed this repository's per-platform outputs of the skills to platform packages.

A migration tool that has kept twelve OKF bundles for months checks its deterministic projections (a bundle rendered as a skill, generated indexes) by regenerating them and comparing, in pre-commit, with nothing to record after a refresh; its design meetings add that a projection can be frozen, after which it is no longer flagged[^tool]. Hashes recorded at the last refresh are state that can itself drift, and a deterministic projection does not need them. The owner chose to check drift according to a projection's nature. The rest of ADR-0019 stands; it is restated here so this ADR is complete.

# Decision

1. **A projection is a directory `knowledge/projections/<slug>/`**, with:
   - `projection.yaml`, its manifest;
   - `content.md`, its content (for a recomputable projection, the procedure);
   - `render/<renderer>.md`, one input per renderer, when it is rendered;
   - `deliverables/`, the rendered files (DOCX, PDF…), latest version only.
2. **`projection.yaml`** declares:

   | Key | Required | Meaning |
   |---|---|---|
   | `lifecycle` | Yes | `canonical` (here to stay; refreshed when its refs change), `deliverable` (versioned and shared outside), `transient` (one-shot; not committed) |
   | `nature` | Yes | `rendered`, `composed` or `recomputable` (decision 4) |
   | `intent` | Yes | Audience, scope, tone and what to leave out; it guides every refresh |
   | `refs` | Rendered and composed: yes | The base concepts and projections it derives from, as bundle paths; a composed projection records each as `{ path, sha256 }` |
   | `render` | Rendered: yes | The command that produces it from its refs, deterministically |
   | `frozen` | No | `true` when the projection is archived: it keeps its last state and is no longer checked for drift |
   | `versions` | Deliverable | One entry per delivered version: `version`, `date`, `commit`, and to whom it was sent |

3. **Dependency rule**: a projection may reference the base and projections at least as stable as itself: `canonical` → base and `canonical`; `deliverable` → base, `canonical` and `deliverable`; `transient` → anything. Removing a transient projection can break nothing else.
4. **Drift is checked according to the nature:**

   | Nature | What it is | How drift is checked |
   |---|---|---|
   | `rendered` | A deterministic function of its refs (a glossary built from the terms, a bundle rendered as a skill) | Run `render` and compare with what is committed; any difference is drift. Nothing is recorded |
   | `composed` | Prose a person or a model selected and wrote from its refs | A ref whose current hash differs from the recorded `sha256` |
   | `recomputable` | `content.md` is a procedure over an external source; the render holds the dated values | Run the procedure again and compare |

   The check lists what drifted and never regenerates it. A refresh proposes the change and a person approves it; for a composed projection the hashes are then recorded again. A frozen projection is not checked.
5. **A projection is not OKF.** OKF tools skip `projections/` ([ADR-0021](/base/decisions/ADR-0021-three-layers-with-open-questions.md)). Projection tools own it: a check of `projection.yaml`, the dependency rule and drift, and the steps to create, refresh and render a projection. After a distillation, `okf-distill` reads only the `refs` of each `projection.yaml` to list the projections to refresh.
6. **Vocabulary**: "projection" means a knowledge projection. The per-platform outputs of this repository's skills are **platform packages**: link packages (the symlinks) and generated packages (`make plugin`, `make m365`, `make copilot`). ADR-0007's decision does not change, only its word, so it is not superseded.

# Alternatives considered

| Alternative | Pros | Cons | Reason rejected |
|---|---|---|---|
| ADR-0019: content hashes for every projection | One rule | A deterministic projection gains state that can drift, for nothing | Regenerating and comparing is exact and needs no bookkeeping |
| Regenerate and compare every projection | No hashes at all | Prose written by a person or a model is not reproducible | Composed projections keep the hashes |
| The manifest in the frontmatter of the projection's `index.md` | Stays inside OKF | Treats a derivation as knowledge | A projection is not knowledge |
| Rendered files outside the bundle | No binaries in `knowledge/` | Separates the deliverable from its projection | The owner keeps them with their projection |
| Regenerate drifted projections automatically | Always fresh | Rewrites what nobody asked to change | A person approves every refresh |

# Consequences

- Positive: deterministic projections cannot drift unnoticed and carry no bookkeeping; composed ones keep a precise record of what they were written from; frozen ones stop raising noise; the KDD context architect gets a defined hand-off.
- Negative / accepted debt: a third nature to implement and document; a rendered projection needs a reproducible `render` command; binaries enter the repository inside `deliverables/`.
- Follow-up actions: those of ADR-0019, with the check branching by `nature` and honouring `frozen`.
